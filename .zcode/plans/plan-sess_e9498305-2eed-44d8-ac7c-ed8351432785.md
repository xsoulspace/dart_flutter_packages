# `dart_changesets` — a changesets-like release engine for Dart (extraction-ready)

Amendments per owner: package named **`dart_changesets`** (generic, so it can be extracted to a standalone repo later — no xsoulspace branding in the package, CLI, or workflows; zero imports from repo-internal tooling such as `registry/tools/**`, self-contained config discovery), and explicit attribution to the original TS changesets + `@changesets/action`.

Everything else as agreed in the prior plan.

## Context — four-system analysis (unchanged)

- **intentcall**: publish leg already solved in Dart, production-proven (`publishRelease`: static check → skip-existing → dependency wait → strict dry-run → `--force` → wait-visible) + measured pub.dev constraint: automated publishing is ref-gated per package tag — per-tag fan-out with dependency waits is the mandated architecture.
- **mcp_flutter / oka**: single-train release-please works but every repo hand-maintains package lists, order arrays, and sync scripts that rot; OIDC-mint lesson (short-lived JWTs) noted.
- **skill_steward**: contract-over-scripts pattern (declared gates + config) shapes the config design; runtime is Node, so the tool is built in Dart.
- **Gap**: nothing in the Dart ecosystem implements the changesets *model* (intent files → assembled version PR → graph-aware dependent cascade → per-package cadence). melos/firehose/Changie/release-please each cover fragments only. The changesets model also removes the conventional-commits dependency.

## Architecture (unchanged in substance)

```
PR: `dart run dart_changesets add` → .changesets/<name>.md (frontmatter: package: bump-type + prose)
merge → assembly Action consumes pending changesets → affected set = declared + transitive dependents
  → ONE "chore: version packages" PR (pubspec bumps + changelogs + dependent constraints, package:pub_semver math)
merge → per-package tags <package>-v<version> → per-tag publish Action (static checks → skip-existing →
  dep wait → dry-run → OIDC publish → wait-visible; never-published ⇒ typed first-publish bootstrap failure)
```

## Files

**New package `pkgs/dart_changesets/`** (pure Dart, self-contained, extraction-ready):
1. `lib/src/changeset.dart` — intent-file model + frontmatter parser (`package:yaml`).
2. `lib/src/workspace_graph.dart` — pubspec parsing, dependency/reverse-dep graph, publishable/private classification (own code; patterns informed by `registry/tools/_registry_workspace.dart` but no imports).
3. `lib/src/bump.dart` — semver bumps + dependent cascade policy via `package:pub_semver` (no regex version math; `^0.x` carets cascade on minor).
4. `lib/src/apply.dart` — version-PR materialization: pubspec edits, changelog assembly, dependent constraint rewrites, consumed-changeset deletion, tag list emission.
5. `lib/src/doctor.dart` — gates (no path deps in publishable set, no publishable→private deps, sdk-floor uniformity) + pub.dev presence census.
6. `lib/src/publish.dart` — port of intentcall's `publishRelease` with attribution comment.
7. `bin/dart_changesets.dart` — CLI: `add`, `status`, `version [--check]`, `doctor`, `publish-tag --tag <pkg>-v<semver> [--execute]`.
8. `README.md` — **attribution section**: design inspired by [changesets](https://github.com/changesets/changesets) and its GitHub Action [@changesets/action](https://github.com/changesets/action); differences documented (Dart/pub ecosystem: `pubspec.yaml`, `pub_semver`, pub.dev OIDC ref-gated publishing, workspace graph from pubspecs).
9. `test/` — golden-fixture unit tests (synthetic in-memory workspaces; no network).

**Repo wiring**
10. `.changesets/` directory + first example intent file + `changesets.yaml` config (private packages, bump policies, changelog conventions).
11. `.github/workflows/dart_changesets_assemble.yml` — main-push assembly (version `--check` → open/update the version PR).
12. `.github/workflows/dart_changesets_publish.yml` — tag `*-v*` fan-out: `id-token: write`, environment `pub.dev`, flutter pinned 3.50.0, global concurrency group, workflow_dispatch rescue.
13. `.github/workflows/registry_publish.yml` — push trigger removed + PAUSED banner (ADR pointer).
14. `PUBLISHING.md` rewrite — dart_changesets flow, bootstrap runbook (first manual publish per new package + per-package automated-publishing toggle, tag pattern `<package>-v{{version}}`, 12/day new-package cap), registry PAUSED.
15. `docs/decisions/<next-free>_dart_changesets_release_engine.md` + index — build-vs-adopt analysis, ref-gating constraint, engine-lane rule (private packages publishable only when a publishable package needs them; conversion = path→hosted rewrite in topo order), attribution to TS changesets.
16. `justfile` — `changesets-add`, `changesets-status`, `release-gate`, `publish-preflight <pkg>`; deprecation comments on `registry-*`.
17. `AGENTS.md` operational desk — new commands.

**Bootstrap (owner, runbook'd)**: per-package pub.dev "Automated publishing" enablement after each first manual publish; ~67 never-published packages spread across days or a pub-dev limit-raise request.
