# Redesign xsoulspace_monetization_foundation widgets: material-free, slot-based composition

## Context (analysis findings)

The widgets folder (`pkgs/xsoulspace_monetization_foundation/lib/src/widgets/`, 6 files) hard-couples monetization UI to Material:

- **`purchase_screen.dart` / `subscription_screen.dart`** — `Scaffold` + `AppBar` + `FutureBuilder` + `CircularProgressIndicator` + `ListView` + `ListTile` + `ElevatedButton`; SubscriptionScreen also shows hardcoded-English `SnackBar`s via `ScaffoldMessenger` after `await` (unmounted-context hazard). Both call `PurchaseProvider` directly with `discarded_futures` ignores, bypassing the package's own command/resource architecture.
- **`purchase_guard_screen.dart`** — good guard shape (`child`/`hasAccess`/`onPurchase`) but renders `CircularProgressIndicator`/`Text`/`ElevatedButton` internally and owns the access future itself.
- **`ad_free_screen.dart`, `family_plan_screen.dart`, `pricing_screen.dart`** — empty stubs that `throw UnimplementedError()`; material import unused.
- **Stray material import outside widgets**: `src/commands/cancel_subscription.cmd.dart` imports `flutter/material.dart` but uses only `@immutable` (needs `foundation.dart`).

Key facts: **zero consumers** of any of these widget classes in the workspace (grep over all `*.dart`; no package depends on this one in pubspec), so the API can be redesigned breaking-change-free. The package already models the state the screens improvise: `AvailableSubscriptionsResource` (holds `LoadableContainer<List<PurchaseProductDetailsModel>>` with `isLoading`), `SubscriptionStatusResource`, `PaywallSelectedSubscriptionResource`, `PurchasePaywallErrorResource` — but per the chosen pure-presentation design the widget layer stays decoupled from those resources (apps wire resources → widgets themselves).

north_star_impact: `applies` — package-internal structural change via the native workflow and validation gate; no repo-center amendment, no ADR.

## Design: pure presentation, properties + builder slots

Rules for every shipped widget:

1. **Import only `flutter/widgets.dart`** (or nothing). No `material.dart` anywhere in `lib/`.
2. **Data flows in as properties; actions flow out as callbacks.** No `FutureBuilder`, no provider calls, no snackbar/dialog/spinner inside the package, no hardcoded strings (all user-facing text comes from the app via builders).
3. **Every visual is a required builder slot** — zero default visuals. Only structural containers from `widgets.dart` primitives (e.g. `ListView.builder`, `Column`) are allowed inside, since they carry no Material look.
4. Screen names retire (`*Screen` → `*View`/`Gate`) — no consumers exist.

### New files

**`src/widgets/purchase_products_state.dart`** — sealed view-state:
```dart
sealed class PurchaseProductsState {
  const PurchaseProductsState();
}
class ProductsLoading extends PurchaseProductsState { const ProductsLoading(); }
class ProductsError extends PurchaseProductsState { final Object error; const ProductsError(this.error); }
class ProductsReady extends PurchaseProductsState { final List<PurchaseProductDetailsModel> products; const ProductsReady(this.products); }
```

**`src/widgets/purchase_list_view.dart`** — replaces `PurchaseScreen`:
- Props: `PurchaseProductsState state`, `ValueChanged<PurchaseProductDetailsModel> onBuy`.
- Slots: `WidgetBuilder loadingBuilder`, `Widget Function(BuildContext, Object error) errorBuilder`, `ProductItemBuilder itemBuilder` (typedef `Widget Function(BuildContext, PurchaseProductDetailsModel)`).
- Internals: `switch (state)` → delegate to the matching builder; `ProductsReady` renders `ListView.builder(itemCount, itemBuilder: (_, i) => itemBuilder(context, products[i]))`. No buy button anywhere — the app's item builder wires `onBuy`.

**`src/widgets/subscription_list_view.dart`** — replaces `SubscriptionScreen`: same shape; `onSubscribe: ValueChanged<PurchaseProductDetailsModel>` instead of `onBuy`. Subscribe success/failure feedback becomes the caller's concern (removes the SnackBar and the context-after-await bug structurally).

**`src/widgets/purchase_gate.dart`** — replaces `PurchaseGuardScreen`, now stateless:
- Props: `required bool hasAccess`, `required Widget child`, `VoidCallback onPurchase`.
- Slots: `WidgetBuilder loadingBuilder`, `Widget Function(BuildContext, Object error) errorBuilder`, `WidgetBuilder lockedBuilder`.
- Behavior contract: `hasAccess ? child : lockedBuilder(context)`; `loading`/`error` states come via optional `PurchaseProductsState`-style props — simplest: props `isLoading: bool` and `loadError: Object?` checked before `hasAccess`. The access future + re-check-after-purchase lifecycle moves to the caller (documented in the doc comment).
